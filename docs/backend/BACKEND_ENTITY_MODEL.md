# MUC PRO SUITE — Definitive Persistent Entity Model

**Status:** target architecture lock. Names describe the required conceptual model; exact Prisma model names may use `snake_case` database mappings. `PK` means UUID unless stated otherwise.

## Entity inventory

| Domain | Entity / class | Purpose, key fields and relationships | Integrity, history, lifecycle |
| --- | --- | --- | --- |
| Platform | `user` — PERSISTED | PK; email, username, password_hash, status, failed_login_count, locked_until, last_login_at. Optionally 1:1 with student/faculty. | Unique normalized email and username; password hash and security fields private. Archive/deactivate, never erase records referenced by history. Audit all access/security changes. |
| Platform | `role`, `permission`, `role_permission` — CONFIGURATION | Role/permission catalog and N:M grant. Permission is `{domain}.{resource}.{action}`. | Unique role code/permission code and pair. System roles protected from casual deletion. |
| Platform | `user_role_assignment` — PERSISTED | User↔role association, assigned/revoked by user, active window. | Unique active user/role assignment. Multiple roles permitted only if explicit. Audit. |
| Platform | `domain_assignment` — PERSISTED | Domain-scoped grant for a `DOMAIN_ADMIN`: domain code, optional department/program scope, effective dates. | One user can hold multiple domain assignments. Unique active grant per same scope. No implicit Master Admin grant. |
| Platform | `audit_log` — AUDIT/HISTORY | Actor/request ID, action, resource type/ID, outcome, before/after redacted JSON, IP, user agent, timestamp. | Append-only/immutable; index resource and actor/timestamp. Secrets, password hashes, raw payment payloads and sensitive document contents excluded. |
| Platform | `idempotency_key`, `outbox_event` — AUDIT/HISTORY | Request key/scope/outcome and post-commit integration event/payload/status. | Unique `(actor_or_client, key, operation)`; immutable completed result. Outbox drives asynchronous delivery. |
| Platform | `backup_record` — AUDIT/HISTORY | Backup manifest/location/checksum/status/started/finished/requester. | Metadata only; unique external backup identity; cannot claim a backup completed without verification. |
| Academic | `academic_year` — CONFIGURATION | Code, date range, active state. | Unique code; date range valid. Exact operational dates remain a required decision. Archive, restrict while referenced. |
| Academic | `academic_term` — CONFIGURATION | FK academic_year; ODD/EVEN, ordinal, dates, status. | Unique `(academic_year, ordinal)` and `(academic_year, term_type)`. One academic year has two terms. |
| Academic | `shift`, `period_definition` — CONFIGURATION | Two fixed shifts; period keys H1–H5, start/end time, display order. | Unique shift code and `(shift, H1..H5)`. Seed/lock the authoritative times; no H6+. |
| Academic | `department` — PERSISTED | Code, name, optional active HOD FK to faculty. | Unique code; HOD relationship history should be `department_leadership_assignment`, not a mutable fact alone. Archive rather than delete. |
| Academic | `program` — PERSISTED | FK department; code/name; UG/PG; duration years, total semesters, shift, funding type, eligible-gender policy, regulation. | Unique code. | Academic | `curriculum_version`, `program_subject` — PERSISTED | Program/regulation version; subject code/name/credits/type and semester number. | Unique program+regulation and `(curriculum, subject_code)`; program subject unique at appropriate semester. | Academic | `academic_class` — PERSISTED | FK academic_year, program, term/program semester, academic year-of-study, class code/status. | Unique `(academic_year, program, academic_year_of_study)`. This is the normal course/year class. **No default section entity or A/B/C generation.** |
| Academic | `student`, `faculty` — PERSISTED | Student: registration/admission numbers, identity/guardian/contact, admission program. Student current state is convenience only; history is enrollment. |
| Academic | `student_enrollment` — PERSISTED/HISTORY | FK student, academic_term, academic_class, program, department, curriculum; semester/year-of-study, shift snapshot, status, effective dates. | Unique student+term; indexes by class/term and student/history. | Academic | `teaching_assignment`, `class_advisory`, `department_leadership_assignment` — PERSISTED/HISTORY | Faculty↔program subject/class/term assignment; advisor/class and HOD/department assignments. | Unique active assignment per faculty/class/subject/term; all effective-dated and audited. | Finance | `fee_structure`, `fee_structure_component`, `fee_installment_rule` — CONFIGURATION/VERSIONED | Term/program/shift/category applicability, effective version, components and optional installment rules. | Unique effective applicability/version. | Certificates | `certificate_type`, `certificate_fee_rule`, `certificate_request` — CONFIGURATION/PERSISTED | Dynamic type and fee configuration; requester user/student/faculty, purpose, state, financial charge link if charged. | Unique active duplicate guard `(requester, type)` under defined states. | Reporting | dossier/KPI/shortage/defaulter/analytics models — DERIVED/VIEW | Response/query models composed from authoritative facts. | No duplicate persistence. Add a database view/materialized view only after measured query need. |

## Required historical context

`student_enrollment` is the anti-corruption boundary for changing student state. Each attendance session/entry, result entry, fee account/charge, assessment, timetable version/slot where relevant, and placement application must preserve its term/program/class/semester context through FKs to enrollment and associated term entities. A current student’s program, semester, status, or advisor must never rewrite these records.

## Explicit non-entities / derived values

- Attendance percentage, condonation/redo status, student/faculty workload, active library-loan count, library clearance status, fee balance/outstanding/status, capacity remaining, event metrics, selection percentage, grade aggregates, SGPA/CGPA, dashboards and report KPIs are derived from authoritative records.
- `FeeStructure.totalAmount`, `StudentFeeAccount.netPayable`, `paidAmount`, and `outstandingAmount` in mocks are display caches today. Target totals are calculated from components/postings; a read model/cache, if introduced later, is rebuildable and never authoritative.
- Current `SectionEntity`/`sectionId` and arrays such as `Subject.facultyIds`, drive allowed-course IDs, and event target IDs are frontend conventions. The target uses explicit relation tables and has no assumed A/B/C section table.
- Hostel and transport are explicitly excluded. Mobile leave, HR/payroll, substitutions, study material and assignments appear in mocks, but requirements are insufficient to lock them as production persistent modules. Assignment may be designed later as Faculty App authorship → Student App submission; do not add a Master Admin assignment module.
